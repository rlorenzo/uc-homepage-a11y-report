About this report

On the first of every month a GitHub Actions workflow loads each UC web property — campus homepages, admissions sites, and the schools and colleges under each campus — in headless Chromium at both mobile (375px) and desktop (1440px) viewport widths, runs axe-core (via @axe-core/playwright), and records the results. Each page is given time to reach network idle before analysis. Issues found only at the mobile width are reported separately in the Mobile column. The headline required metrics track WCAG 2.0 and 2.1 Level A and AA success criteria — the baseline mandated under ADA Title II and Section 508. WCAG 2.1 Level AAA and all of WCAG 2.2 are recorded separately as reach goals: aspirational, not yet legally required in the US.

Automated testing is a floor, not a ceiling. axe-core catches roughly 30 to 40 percent of real accessibility barriers. A clean scan is a great starting point — it does not mean a site is fully accessible. Manual review, assistive-technology testing, and — above all — testing with disabled users remain essential.

The goal of this report is not compliance for its own sake. It is to keep accessibility visible month over month, so that the University of California's public web presence works for the widest possible audience.
